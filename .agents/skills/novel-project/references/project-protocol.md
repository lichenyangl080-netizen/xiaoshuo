# 项目协议与档案

## 作者主导的协作与代笔

作者负责思想、重要选择和最终修改；助手帮助梳理、推敲与代笔。相关回查与维护由助手按需完成，不要求作者每章填表、走固定流程或逐项确认。

代笔前理解作者本次的场景目的、人物动机与情绪方向，并读取相关前文；可以补足不改变这些意图的动作、感官和衔接。关键选择、新的力量规则或重要关系变化不能作为普通润色擅自加入；遇到真正影响走向的缺口，指出分歧，不替作者定案。

风格以作者认可或修订过的正文为参照，优先结合相邻章节；持续保留作者反复指出的具体语言偏好及必要原文定位。没有认可样本时不声称已掌握作者文风。保持叙述视角、用语和表达习惯的延续，允许场景情绪、人物成长带来合理变化，不机械统一句长、节奏或所有人物的声音。

## 决策与证据

内容可标为：已确认、暂定、候选、举例、否决、待研究。每项重要决定记录来源、理由和影响；未经作者选择，AI方案保持候选。作者原始文档原样保存，最新明确决定可替代旧决定，但保留变更原因。

作者改稿优先于旧计划；若与既定核心规则冲突，列出原文和影响，不能替作者默默补设定。试写不能充当定案证据。作者认可某个局部，不等于采纳整套方案或该稿中的所有新增设定。

## 按实际内容建档

目前入口为 `项目档案/当前进度.md`。出现实际内容后按需建立以下文件，不为凑结构填写虚构事实：

- `项目档案/设计决定.md`：状态、来源、理由、后果、替代关系。
- `项目档案/世界与修炼.md`：规律、代价、限制、制度与生活影响。
- `项目档案/人物.md`：欲望、决策内核、认知与关系、状态变化。
- `项目档案/真相与认知.md`：事实、文明解释、人物所知/误解、读者所知、证据与获知时间。
- `项目档案/伏笔与因果.md`：首次出现、当时含义、真实原因或候选、揭示条件、因果后果、兑现状态。
- `项目档案/大纲.md`：远期方向、中期节点、近处情节；各层保留确定程度。
- `项目档案/连续性.md`：时间线、地点、状态、资源和变化依据。
- `项目档案/开放问题.md`：问题、候选、关键分歧、下一项需要的证据。
- `研究/`：按实际专题存研究；`正文/草稿/`、`正文/作者修订/`、`正文/确认稿/` 按需保存不同版本。

共用稳定编号与来源定位即可，不强制填满表格。档案与原文有差异时回查原文，不用摘要覆盖证据。

## 本书约束的用法

第三人称限知为主。底层规律的作者解释与读者看到的玄幻体验分开；不把神魂、心智与意识自动合并。穿越、地球记忆和终局机制的当前确定程度查当前进度及相关专题，不由技能固定。

仅在采用歌谣情节时，相关记录才需包含版本差异、听见的人、时机、当时解释、验证证据和危机规则。变化应帮助理解规则，不能把未定的藏字密码或古老版本假说写成事实。

主角特殊经历按实际情节检查机会的条件、人物选择与后果；有代价时核对其因果，不为满足清单强加损失或下一次机缘。检查其他聪明人拥有的信息和限制，避免仅靠巧合、主角独占智力或官方无能推进。采用共同破局时，各人的信息、能力与行动贡献须成立；具体分工服从作者当前选定的情节，不固定为主角发现信息、强者执行。

## 相关前文与章节状态

讨论或代笔涉及旧事、人物、能力与关系时，按本次需要查阅档案和必要正文，避免凭印象补成已发生的事实。重要状态保留来源与生效时间，按所写章节的时间点核对；不能把人物后来知道的信息、取得的能力或形成的关系提前套用。找不到依据时标明不确定；仅当缺口会改变本次写作时向作者询问，不因此要求全量重读或停下无关工作。

## 更新与保护

记录用户已明确选择的内容可以作为相关任务的正常收尾；只有咨询、审阅或分析请求时不擅自改正文或定案。变更涉及哪些档案就更新哪些，不重复复制全文。

作者修改、原始资料和确认稿不被新生成稿覆盖；局部编辑按用户指示进行，重大改稿另存版本。不会因为技能推荐 Git 就自行提交、推送或回滚。检查必须报告实际范围，未检查的内容不能标成通过。
