# 小说项目协作

## 开始

以包含 `AGENTS.md` 和 `项目档案/` 的项目根目录为路径基准。读 `项目档案/当前进度.md`，按需查作者原始设计及相关档案。未读前文或未建立档案时如实说明，不假装具备完整记忆。

用户提供的原始文档不是完整定稿。设计原则、暂定骨架、偏好、候选、举例、已否决方向需要区分。正文代笔、改稿、定案或档案更新前，读 [项目协议](references/project-protocol.md)，落实作者意图、风格参照、相关前文回查及记录边界。

## 按任务选模块

只读取本次需要的模块，直接讨论可以不调用辅助技能：

- 世界规律、修炼与社会：读 [novel-world](../novel-world/SKILL.md)。
- 人物选择、成长和关系：读 [novel-character](../novel-character/SKILL.md)。
- 全书路线、卷纲、场景与章纲：读 [novel-outline](../novel-outline/SKILL.md)。
- 接续、保存决定与维护档案：读 [novel-memory](../novel-memory/SKILL.md)。
- 检查逻辑、信息与前后状态：读 [novel-continuity](../novel-continuity/SKILL.md)。
- 场景对白与人物声音：读 [novel-dialogue](../novel-dialogue/SKILL.md)。
- 拆书研究：读 [文本研究方法](references/research.md)。

## 构思与写作

先理解作者想要的效果，再指出问题、拓展有实质差异的方向；每个重要方案说明收益、代价、依赖条件与对既有内容的影响。用户只要求分析时不擅自修改正文或将方案定案。

明确章纲或写作要求足以开写时直接执行。缺少关键选择时先推进不依赖它的工作，只就会显著改变故事的分歧询问。不要每个步骤都要求确认。

初稿按已授权范围写；修改优先处理作者本次指出的问题；发现影响该修改的实质冲突时说明依据与影响，不自行扩大改稿范围。可多次修订，不强制固定三稿、固定章数或固定节奏。未经作者认可，草稿新增内容保持草稿状态，不流入正式档案。

人物首先依其欲望、信息与处境行动。允许日常、幽默、情绪和阅读回报；不把合理性等同于没有爽感，也不为爽感扭曲人物和世界。

自动调用是本次任务内选择方法，不创建后台任务，不自动连写。具体设定保存在项目档案中，不塞进技能；参考材料不覆盖作者意图。
